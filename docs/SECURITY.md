# الأمان (Security)

| المجال | التطبيق |
|---|---|
| كلمات المرور | `scrypt` عبر Werkzeug؛ سياسة ≥ 8 أحرف بحروف وأرقام (≥ 10 لحسابات الإدارة عبر CLI)؛ لا تخزين نصي |
| الجلسات | كوكي `HttpOnly` + `SameSite=Lax` + `Secure` في الإنتاج؛ `session_protection="strong"`؛ مسح الجلسة عند الدخول (منع Session Fixation) |
| CSRF | Flask-WTF على كل POST؛ واجهة API تشترط `X-CSRFToken` لطلبات الجلسة؛ طلبات Bearer مستقلة عن الكوكي |
| حقن SQL | SQLAlchemy ORM بمعاملات مقيّدة حصراً؛ لا SQL نصي مُركّب من مدخلات المستخدم |
| XSS | ترميز Jinja التلقائي؛ CSP: `script-src 'self'` بلا سكربتات مضمّنة؛ JSON للبيانات عبر `<script type="application/json">` |
| الترويسات | CSP، X-Frame-Options DENY، nosniff، Referrer-Policy، Permissions-Policy، COOP، HSTS (Nginx) |
| RBAC | مُزيّنات `permission_required` على كل مسار إداري + حارس عام للوحدة `/admin`؛ الموظف لا يرى إلا المسند إليه؛ منع رفع الصلاحيات |
| تحديد المعدل | Flask-Limiter: الدخول 10/د، التسجيل 5/د، الإبلاغ 6/د و40/يوم، المتابعة، الدعم، رموز API |
| الرفع | قائمة امتدادات + فحص محتوى بـ Pillow + حد الحجم + حد العدد + إعادة ترميز (يزيل EXIF/GPS) + اسم عشوائي + تخزين خارج الويب + خدمة عبر مسار مُصرَّح فقط + Nginx يرفض `/uploads` |
| الخصوصية | العرض العام للبلاغ بلا وصف/صور/هاتف؛ الملاحظات الداخلية لا تظهر للمُبلِّغ ولا في API |
| إعادة التوجيه | `safe_next` يمنع Open Redirect |
| تعداد الحسابات | رسالة موحّدة في «نسيت كلمة المرور» ورسالة دخول عامة |
| رموز الاستعادة | itsdangerous موقّعة، صلاحية ساعة، تُبطَل تلقائياً بعد تغيير كلمة المرور |
| رموز API | تُخزّن مجزّأة (SHA-256)، انتهاء صلاحية 30 يوماً، إلغاء فوري |
| التدقيق | `audit_logs` لكل دخول/فشل/تسجيل/تغيير حالة/إسناد/تعديل مستخدم/إعدادات/استيراد |
| الأخطاء | معالج مركزي؛ لا تتبّع أخطاء للمستخدم في الإنتاج؛ تسجيل في `/var/log/irs-road` |
| الأسرار | البيئة فقط (`/etc/irs-road/irs-road.env` بصلاحية 640)؛ رفض التشغيل دون SECRET_KEY/DATABASE_URL؛ رفض SQLite في الإنتاج |
| النظام | خدمة systemd معزولة (ProtectSystem=strict، NoNewPrivileges، مستخدم مخصص بلا Shell) |
| قاعدة البيانات | مستخدم مخصص بصلاحيات على `irs_road` فقط؛ مستخدم نسخ احتياطي للقراءة؛ لا استخدام لـ root |

## توصيات تشغيلية
1. تفعيل Redis لتخزين حدود المعدل المشتركة بين العمّال (`RATELIMIT_STORAGE_URI`).
2. مراجعة `audit_logs` أسبوعياً، وتنبيه عند تكرار `auth.login_failed`.
3. تدوير `SECRET_KEY` يُبطل الجلسات القائمة؛ تدوير مفاتيح VAPID يتطلب إعادة اشتراك الأجهزة.
4. تحديث الحزم شهرياً: `pip list --outdated` ثم اختبار ثم `update.sh`.
